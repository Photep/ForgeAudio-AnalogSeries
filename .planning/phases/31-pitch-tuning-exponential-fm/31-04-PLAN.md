<objective>
Give the pitch chain a body a human can reach.

The core now sums COARSE, FINE and FM into the volt domain, but nothing in Rack can move any of
them. D-16 continues Phase 30's rule that every visible control does something, and its converse:
DSP that no control can reach cannot be auditioned in Rack, and this phase's sign-off is an
operator-driven in-Rack session. So all four controls are declared here, on the same throwaway
panel, with stock widgets, at the final 18HP geometry.

The shell stays a pure index owner. Its banner declares that it does no DSP and that this is
load-bearing, because the headless suite only describes what Rack produces for exactly as long as
that holds. Three `configParam` calls, one `configInput`, five field assignments, four widget
placements, four rectangles.

Purpose: the phase becomes auditable in Rack, and the tune and FM controls read in the units a
musician expects.
Output: four controls that move real DSP, plus corrected comments where the shell's own prose
became false.
</objective>

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Rack patch cable -> `inputs[FM_INPUT].getVoltage()` -> `in.fmVolts` | UNTRUSTED. This assignment is the exact line that makes an unsanitised cable voltage reachable from the exponent argument for the first time; the containment is the core's bound, not this file |
| Rack param widget / patch file -> `params[...].getValue()` | Live edits are sanitised by the SDK's quantity object; a value restored from a patch file is a second path, and this module still persists nothing |
| `src/AnalogVCO.cpp` -> the headless test suite's meaning | If arithmetic ever appears here, `tests/` stops describing what a user hears. This is a correctness boundary the file's banner declares load-bearing |
| `res/AnalogVCO.svg` -> the widget's box size | The panel asset determines the module's geometry; a hardcoded box size would desynchronise them silently at the panel phase |
