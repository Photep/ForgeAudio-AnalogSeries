<objective>
Give the Phase-30 oscillator a body in Rack: a minimum-viable shell that marshals four controls into the POD and delegates every sample to `core.step()`, plus the throwaway 18 HP panel it draws on.

Plan 30-02 made the DSP real but headless — it is proven only by `make test`. This plan is what turns it into something a human can plug a cable into. Nothing here computes anything: the shell owns Rack indices and the core owns arithmetic, and the boundary between them is the same POD the Phase-29 harness drives. If this file ever grows a pitch calculation or an output scaling, the headless tests stop being evidence about what Rack actually produces.

The scope is deliberately, aggressively small (D-07). Four controls, because those are the four the Phase-30 DSP consumes, and a control that does nothing makes an in-Rack check dishonest. Stock SDK widgets (D-08), because the Forge Noir components live inside the shipped LFO's translation unit and this phase's whole guardrail story is that `src/AnalogLFO.cpp` is not in the diff. A panel of six rectangles (D-06), because Phase 35 replaces it wholesale and only the filename and the 18 HP geometry are durable.

The oscillator this shell exposes is **crude and aliased on purpose**. Phase 32 owns band-limiting. Nothing in this plan asserts, or should be judged on, how it sounds.

Purpose: make the architecture audible end-to-end — POD boundary, harness, Rack shell — before any hard DSP lands.
Output: `res/AnalogVCO.svg` and `src/AnalogVCO.cpp`, compiled by every existing gate with no build or CI wiring added.
</objective>
