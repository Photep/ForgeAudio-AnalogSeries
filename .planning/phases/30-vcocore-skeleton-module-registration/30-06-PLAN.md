<objective>
Make the VCO a real module in the plugin — and do it without moving one byte of the module that is already live in the VCV Library.

Three files, three appended lines, one of which is a JSON object. Mechanically this is the smallest plan in the phase. It is also the one with the highest blast radius, because these three files are the only ones Phase 30 shares with the shipped Analog LFO, and because `check_frozen.sh` deliberately does **not** pin them — its banner says so, naming this phase as the reason. Nothing is watching these bytes except this plan.

So the plan spends its budget on two things. First, on not bypassing the operator: the permanent slug `ForgeAnalogVCO` is a one-way door — the SDK documents `Model::slug` as "Never change this after releasing your module", and it is written into every user patch that ever contains the module. That decision was surfaced and taken at plan 30-01, before the phase produced a single commit. This plan verifies the record before it edits, and halts if the record is not there. Second, on proving rather than promising: "the LFO entry is byte-unchanged" is exactly the kind of claim that is true when written and false three refactors later, so it is asserted by diff shape and by a field-for-field comparison of the parsed manifest, not by a sentence.

Purpose: complete PANEL-03 — the VCO appears as a second selectable module with the LFO's registration and slug untouched.
Output: three additive edits and a linked `plugin.dylib` exporting both model symbols.
</objective>
