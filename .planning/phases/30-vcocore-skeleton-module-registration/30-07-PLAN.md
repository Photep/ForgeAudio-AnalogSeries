<objective>
Close Phase 30 on evidence the project has already learned it cannot get locally.

Every plan before this one verified itself, and every one of those verifications passed on the research prototype. That is exactly the state in which v2.0.0 was tagged and rejected from the VCV Library. Phase 29 did not merely note the risk — it reproduced it deliberately: a commit that could not link returned exit 0 from `make test`, `make strict`, `make guards` and `check_canary.sh`, and the strict gate reported success on the Ubuntu runner too. `-fsyntax-only` never invokes a linker on any platform. The only thing that caught it was the CI `toolchain-gate` MinGW link leg.

So this plan has three jobs and none of them is optional. Run the full local gate at the final case count and confirm the ladder across five plans arrives where it should. Push, and **observe** the win-x64 link step conclude `success` on the exact commit — not infer it from an absent failure, because a step that fail-fasts upstream is reported `skipped`, which scans as "not red". Then put the thing in Rack and listen to it, starting with a stale-install flush, because the most likely explanation for a module that does not appear is not a registration bug.

What the listening test is for: confirming that four controls each do something audible, and that the shipped Analog LFO is untouched. What it is emphatically not for: judging how the oscillator sounds. It aliases on purpose and it overshoots ±5 V on purpose. Phase 32 owns the first and Phase 34 owns the second, and a defect report about either would be a report that the phase did what it said.

Purpose: turn "every plan is green" into "the milestone's own standing rule has been satisfied".
Output: an observed-green CI link leg on a named commit, and an operator-confirmed working module beside an unchanged one.
</objective>
