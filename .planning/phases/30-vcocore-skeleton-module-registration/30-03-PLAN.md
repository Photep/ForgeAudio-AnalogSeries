<objective>
Create the CORE-01 behavioral suite for the live oscillator: does it play the right note, does it stay in range, and does a different instance actually sound different.

Phase 29 recorded that its entire local gate returned exit 0 on code that could not link. The lesson that produced is the organising principle of this file: a test that cannot fail is not evidence. So each of the three invariants here is written against the measured trap that would make it vacuous — the pitch case measures the output rather than the telemetry, the magnitude case adds a fixed worst-case scenario because the harness sweep never reaches the overshoot, and the divergence case asserts its own character gating so no future reader can quietly move it to `character = 0` and leave a green test proving nothing.

The oscillator under test aliases on purpose. Nothing in this file asserts anything about spectral cleanliness; Phase 32 owns CORE-02 and the alias floor.

Purpose: turn "the DSP landed" into "the DSP is correct within stated, measured margins".
Output: `tests/test_vco_core.cpp` with its helpers and the three CORE-01 cases, selectable as `-tc="vco core*"`.
