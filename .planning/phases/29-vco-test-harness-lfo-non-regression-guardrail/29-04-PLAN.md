<objective>
Add the two remaining LFO tripwires and wire the whole guard suite so nothing can rot.

**D-05 — frozen-header hash guard.** A checked-in SHA-256 manifest plus a verifier that hard-fails when a frozen file is edited without a deliberate manifest bump.

**A scope note that must stay visible.** D-05 names four headers. The LFO's actual behavioral include closure is eleven, and three of the seven unlisted ones — `PatchParse.hpp`, `DisplayFill.hpp` and `Anim.hpp` — have **zero** golden coverage and are precisely the headers `.planning/research/ARCHITECTURE.md` flags as reuse candidates for the VCO shell in Phase 35. A literal four-header manifest would leave the single most likely silent-regression surface in the milestone unguarded. This plan therefore implements a **strict superset**: the four named headers plus the rest of the closure, the shipped shell, and the two test files that are otherwise their own only witnesses. This extends the locked decision additively and contradicts nothing in it — the same one-line bump D-05 already anticipates for `DriftEngine.hpp` in Phase 34 is the escape hatch for any of the extra entries. The rationale is written into the verifier's banner so a future reader sees why the manifest is larger than D-05's text.

**D-06 — dependency-direction audit.** A static gate asserting that VCO work cannot leak into the LFO build: no LFO translation unit includes a VCO file, VCO headers are Rack-free and include only siblings plus standard headers, no second `forge::Inputs` is ever declared (the cross-translation-unit ODR trap), and no hashing implementation escapes into `src/`.

**And the wiring, because an unwired guard is the failure mode this repo has already demonstrated.** `tests/check_docs.sh` is a complete, well-written gate that has been invoked by nothing since Phase 27. Every guard added here gets a CI step, `make guards` runs the whole suite locally, and a standing audit asserts the wiring stays in place.

Both new guards ship with **negative controls that run on every invocation** — a perturbed synthetic copy for the hash guard, a synthetic violating fixture for the include audit — because a guard that has only ever been observed green is unvalidated.

Purpose: complete TEST-04's tripwire half and give TEST-06's canary guard a local runner.
Output: `src/dsp/FROZEN.sha256`, `tests/check_frozen.sh`, `tests/check_includes.sh`, a `guards` Makefile target, and two appended CI steps.
</objective>
