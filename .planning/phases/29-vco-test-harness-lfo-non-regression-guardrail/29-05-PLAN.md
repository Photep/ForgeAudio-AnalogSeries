<objective>
Close Phase 29 by proving the guardrail actually works, rather than asserting that it does.

Two things happen here. First, one local gate run establishes the standing command set that every subsequent phase will repeat: `make test` (VCO harness plus the six shipped-LFO golden replays plus the D-04 byte lock), `make strict` (the C++11 pedantic gate over the VCO translation unit), and `make guards` (the D-05, D-06 and D-07 guard scripts with their built-in negative controls).

Second — and this is the part that makes ROADMAP success criterion 3 a demonstration instead of a claim — the **D-07 ODR link gate gets its negative control in CI**. Research measured this precisely: Apple clang materialises an in-class `static constexpr` array as a per-translation-unit local symbol and links the v2.0.0 failure class cleanly at both `-O0` and `-O3`. There is **no local substitute** for the CI MinGW link leg, and a task asking for a local reproduction would silently pass and report a false green. So the operator pushes a deliberately broken canary on a throwaway branch, observes `toolchain-gate` fail with an undefined reference, and reverts.

That exercise also re-confirms pitfall P-2 as a recorded observation: `make strict` will report PASS on the broken code. Green `make strict` plus green `make test` was exactly the state in which version 2.0.0 was tagged and rejected. Writing that observation down is part of the deliverable.

Output: a recorded local gate run, an observed red-then-green CI cycle for the ODR gate, and a completed `29-VALIDATION.md`.
